# REVIEW.md — критерии авторевью

Этот файл попадает в промпт авторевью (`.github/workflows/review.yml`). Ревьюер читает diff,
описание PR, спецификацию (`docs/spec.md`) и тикеты по ссылкам из описания, статусы CI.

## Что проверять

1. **Соответствие спецификации и согласованию.** Сверить PR со спецификацией и тикетами из
   описания. Нет ссылок на спецификацию, тикет или согласование — сказать об этом. Изменение
   выходит за объём тикета — перечислить, что именно.
2. **Занятый слот недоступен повторно.** После бронирования слот не должен выдаваться в
   списке свободных и не должен бронироваться снова — ни тем же Типом встречи, ни другим.
3. **Полуоткрытые интервалы `[start, end)`.** Встреча может начаться в момент окончания
   предыдущей; частичные пересечения запрещены. Искать ошибки границ: `<=` вместо `<`,
   включённый конец, сравнение только начал.
4. **Окно записи — 14 календарных дней.** Окно сдвигается со временем; границы, часовой пояс
   и шаг стартов — по спецификации. Искать off-by-one на первой и последней дате окна.
5. **`Clock` вместо `now`.** «Сейчас» берётся только из внедряемого `Clock`. Прямые
   `Instant.now()`, `LocalDate.now()`, `Date.now()`, `new Date()` в логике — дефект.
6. **Гарантия на уровне БД.** Запрет пересечений держится при одновременных запросах:
   exclusion constraint или блокировка в транзакции, а не только проверка в коде. Проверка
   «прочитал — убедился, что свободно — записал» без ограничения в БД — дефект.
7. **Контракт.** Изменения API начинаются с `api/main.tsp`; `openapi.yaml` и `schema.d.ts`
   сгенерированы, а не правлены вручную; DTO backend совпадают со схемами.
8. **Тесты и CI.** Новое поведение покрыто тестом, который упал бы без изменения; статусы CI
   относятся к head SHA PR.

## Формат замечания

Каждое замечание — отдельный пункт из четырёх частей:

- **Файл** и **строка** (`path/to/File.kt:42`);
- **Условие ошибки** — при каких входных данных или состоянии проявляется;
- **Последствие** — что увидит пользователь или что сломается.

Без всех четырёх частей замечание не пишется. Догадки без условия ошибки не включать.

## Если дефектов нет

Сказать прямо: «Дефектов не найдено», и перечислить, что проверено (пункты выше, номера
файлов). Не придумывать замечания ради объёма.

## Что не обсуждать

Форматирование, стиль, имена, порядок импортов — это делают линтеры (`mise run lint`).
